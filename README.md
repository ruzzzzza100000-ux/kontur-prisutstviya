# Контур присутствия — облачный демо-MVP

## Самый простой путь: GitHub + Render

**Стоимость старта:** можно попробовать на бесплатном тарифе Render. Бесплатный сервис может засыпать после периода без активности, а локальная SQLite-база на бесплатном Render НЕ является постоянным хранилищем. Данные могут пропасть после перезапуска, простоя или нового развёртывания. Поэтому используйте этот запуск только для проверки сайта и не загружайте данные клиентов или секреты рекламных кабинетов.

### Шаг 1. Создайте репозиторий GitHub
1. Откройте https://github.com/ и войдите или зарегистрируйтесь.
2. Нажмите **+** → **New repository**.
3. Назовите репозиторий `kontur-prisutstviya`.
4. Для первого теста можно выбрать **Public** (так проще подключить Render) или Private, если ваш аккаунт Render позволяет подключить приватный репозиторий.
5. Создайте репозиторий. Не добавляйте README автоматически, если GitHub предлагает это сделать — в архиве уже есть свои файлы.

### Шаг 2. Загрузите файлы проекта
1. Распакуйте архив `kontur_prisutstviya_cloud.zip` на компьютере.
2. Откройте папку `kontur_prisutstviya_cloud`.
3. В репозитории GitHub нажмите **Add file** → **Upload files**.
4. Перетащите ВСЕ файлы из папки (включая `render.yaml`, `server.py`, `index.html`, `README.md`, `.gitignore`, `sample_metrics.csv` и `run_windows.bat`) в корень репозитория. Не загружайте папку-обёртку вместо её содержимого.
5. Нажмите **Commit changes**.

### Шаг 3. Разверните сайт на Render
1. Откройте https://render.com/ и зарегистрируйтесь.
2. В Render Dashboard нажмите **New** → **Blueprint**.
3. Подключите GitHub и разрешите доступ к созданному репозиторию.
4. Выберите репозиторий `kontur-prisutstviya`. Render найдёт `render.yaml`.
5. Подтвердите создание Blueprint и выберите бесплатный тариф, если Render попросит подтвердить тариф.
6. Если попросит значение `BRAVE_SEARCH_API_KEY`, оставьте его пустым на первом этапе или добавьте свой ключ поискового API. Для добавления ключа позже откройте сервис → **Environment** → добавьте `BRAVE_SEARCH_API_KEY` → **Save, rebuild, and deploy**.
7. Дождитесь статуса **Live** и нажмите публичную ссылку вида `https://kontur-prisutstviya-demo.onrender.com`. Если имя уже занято, Render может добавить суффикс к URL.

### Шаг 4. Проверьте работу
1. Откройте публичный URL.
2. В новом окне откройте `https://ВАШ-АДРЕС/api/health`. Должен появиться JSON со статусом `ok: true`.
3. Введите название тестовой компании в поиск. Без ключа Brave Search сайт покажет внешние поисковые ссылки; при настроенном ключе результаты API отобразятся внутри сайта.
4. Добавьте тестовую ссылку в реестр и обновите страницу — профиль должен загрузиться из SQLite, пока база не потеряна из-за перезапуска/сна.
5. Для проверки аналитики импортируйте `sample_metrics.csv`.

## Что подключено сейчас
- публичный web-сервис и backend API;
- хранение ссылок и импортированных метрик в SQLite;
- проверка сайта компании без ключей (`POST /api/scan`): читает главную страницу и находит ссылки на 2ГИС, Яндекс Карты, VK, Telegram и др., счётчики Метрики/GA и телефоны; адреса во внутренней сети блокируются, частота проверок ограничена;
- поисковый API Brave — по желанию, через серверный секрет;
- импорт/экспорт CSV и сводная аналитика по импортированным строкам.

## Ограничения бесплатного демо
- Бесплатный Render может усыплять сервис после простоя; первый запуск после сна может занять около минуты.
- Файловая система бесплатного web-сервиса временная: SQLite-файл не гарантированно сохранится после сна, перезапуска или нового деплоя.
- Этот демо-MVP не имеет пользовательских аккаунтов и разграничения доступа. Любой, кто знает URL, может открывать приложение и вызывать его API. Не размещайте реальные персональные данные, данные клиентов, рекламные токены или коммерчески чувствительные отчёты.
- Для постоянной работы следующий этап — PostgreSQL, авторизация пользователей, разграничение компаний и резервные копии.
- Публичные профили не подтверждают владение кабинетом. Доступ к закрытой аналитике площадок потребует отдельной разрешённой авторизации/API для каждой площадки.

## Если деплой не запускается
- В Render откройте сервис → **Logs** и посмотрите первую ошибку.
- Убедитесь, что `render.yaml` лежит в корне репозитория рядом с `server.py`.
- После изменений в GitHub Render обычно запускает новый деплой автоматически.
- Локально на Windows можно запустить `run_windows.bat`.
